# TCP 세그먼트
 TCP 프로토콜은 전송을 위해 바이트 스트림을 세그먼트 단위로 나눈다.
 세그먼트는 TCP를 용하여 두 장치 간에 전달하는 데이터 단위이다.

# 3-way 핸드세이킹
 TCP 연결에서 데이터를 전송하기 전에 연결을 확립하기 위해 패킷 요청 과정에서 세 번 교환하는 것.

# ACK
 확인 응답을 ACK(ACKnowledgement)라고 하는데, 확인 응답이 있어야 다음 데이터를 전송할 수 있다.

# 슬라이딩 윈도우
 송신측에서 데이터 전송을 하는 과정에서 버퍼 역할을 하기 위해서 송신 윈도우를 이용하는 방식이다.

TCP 서비스
	TCP(Transmission Control Protocol)는 연결 지향 형태의 신뢰성 있는 프로토콜이다.
	연결 지향형 프로토콜은 신뢰성 있는 데이터 전송을 보장하며, 오류가 발생하면 수신측에 알려준다.
	TCP는 포트 번호를 이용하여 프로세스 간 통신 설정을 한다.
	TCP 프로토콜이 여러 개의 포트번호를 사용해서 상위 계층 프로그램과 각각 통신이 가능하다.
TCP 세그먼트
	TCP 세그먼트(Segment)는 TCP를 이용하여 두 장치 간에 전달하는 데이터의 단위이다.
	20~60 바이트의 TCP 헤더와 응용 프로그램으로부터 발생되는 데이터로 구성되며, 헤더는 기본이 20 바이트이고, 옵션을 포함하는 경우 최대 60 바이트이다.
	TCP 헤더는 송신지 포트 번호, 수신지 포트 번호, 순서 번호, 확인 응답 번호, 헤더 길이, 윈도우 크기, 제어 필드, 검사합, 긴급 포인터, 옵션 필드로 구성된다.
TCP의 주요 기능
	데이터를 전송하기전에 연결을 확립하기 위해 패킷 요청을 세 번 교환하는 것을 3-way 핸드셰이킹이라고 한다.
	전송 단계에서 슬라이딩 윈도우 프로토콜 이용하여 흐름 제어 메커니즘을 제공한다.
	전송 단계에서 응답 패킷, 시간-초과, 재전송 방식을 이용하여 오류 제어 메커니즘 제공한다.
	TCP의 동작을 순조롭게 수행하기 위하여 4가지의 타이머를 사용한다.
